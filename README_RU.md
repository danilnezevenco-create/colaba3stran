# Оптимизация отрисовки техники squadmc

Это патч исходников для твоего существующего проекта Minecraft 1.20.1 / Forge
с приложенной сборкой SBW 0.8.8. В архиве 82 изменённых Java-файла и 4 новых
вспомогательных класса. Готового JAR в нём нет.

## Что сделано

- Все 41 рендерер техники и стационарных установок squadmc используют общий
  OptimizedVehicleRenderer.
- Повороты кубов вокруг собственных точек опоры и их постоянная геометрия
  вычисляются один раз. Каждый кадр применяются актуальные преобразования
  костей, поэтому башни, колёса, гусеницы и остальные анимации продолжают
  обновляться с прежней частотой.
- В цикле вывода геометрии после заполнения кэша не создаются временные векторы
  для каждой вершины и грани; убраны повторные операции со стеком матриц кубов.
- 164 постоянные ссылки на модели, текстуры и анимации вынесены в константы.
- Поиск полей через reflection у четырёх моделей стационарных установок
  выполняется один раз для класса сущности. Неудачные поиски также запоминаются.
- Кэш пересоздаётся при смене объекта загруженной модели, включая перезагрузку
  ресурсов. Это исключает использование старой геометрии после F3+T.

Файлы моделей, текстуры и количество граней не меняются. Отрисовка не скрывает
дальнюю технику, не выключает анимации и не сокращает дальность видимости.
Оптимизация относится к технике из squadmc; рендереры собственных машин SBW
из его JAR этим патчем не заменяются.

## Установка

1. Сохрани копию своей текущей папки проекта.
2. Объедини `src` из этого архива с `src` своего проекта, заменив совпадающие
   Java-файлы. Остальные файлы проекта оставь на месте.
3. Если ты менял эти модели/рендереры после отправки исходного TXT, перенеси
   соответствующие изменения из `performance.patch` в свои актуальные файлы.
   В нём показаны только изменения; в чате полный код не нужен.
4. Собери проект своей обычной командой `gradlew.bat build` и установи новый
   JAR squadmc. Сам этот ZIP в папку `mods` не устанавливается.

Патч содержит только клиентские модели, рендереры и их помощники. Файлы SPIKE,
его урон и метод отрисовки SEEK в архив не входят: твои последние правки этих
файлов сохраняются. Регистрацию мода менять не нужно.

## Результат проверки

Проверка сравнила 22 340 вершин с реальными стандартными методами GeckoLib 4.4.9:
положение, нормали, UV, цвет, прозрачность, освещение и overlay. Максимальная
погрешность вычислений координат — около 0,000031 блока. UV, цвет и значения
освещения совпали точно. Проверены повёрнутые кубы, плоские грани, зеркальные
преобразования, неравномерный масштаб и обновление кэша после смены модели.

В синтетическом тесте одного прохода по 256 кубам после прогрева:

| Проверяемый участок | Время | Временные объекты, байт на проход |
| --- | ---: | ---: |
| Исходный вывод геометрии GeckoLib | 117–123 мкс | около 97 016 |
| Кэшированный вывод геометрии | 48,6 мкс | 0 |

Это примерно 2,5-кратное ускорение только данного участка на проверочном
компьютере. Это не замер FPS в игре и не обещание роста общего FPS в 2,5 раза.
Кэш занимает дополнительную память под подготовленную геометрию; при первом
появлении модели происходит одноразовое заполнение.

## Как сравнить FPS в игре

Используй ту же сцену, настройки графики, число машин и положение камеры.
Отключи ограничение FPS/VSync на время сравнения, если они мешают увидеть разницу.
После загрузки дай моделям появиться на экране и сравни время кадра/FPS в течение
30 секунд: с 10, 30 и 60 машинами, сначала стоящими, затем движущимися.
Проверь также вид из машины, вращение башен, гусеницы и F3+T.

Для сравнения с обычным выводом геометрии добавь в JVM-аргументы запуска:

`-Dsquadmc.disableVehicleMeshCache=true`

После удаления этого аргумента и перезапуска кэш снова включится. Этот
переключатель отключает именно кэш геометрии; константы ресурсов и кэш поиска
полей продолжают работать. Полностью вернуть прежний код можно из копии проекта.

Если после правки время кадра почти не меняется, потребуется профиль именно
твоей сцены: нагрузка может приходиться на видеокарту, частицы, звук или
обновления сущностей. Количество отправляемых видеокарте вершин осталось прежним.

## Ограничения проверки

Четыре новых вспомогательных класса скомпилированы с API Minecraft 1.20.1,
Forge 47.2.0, приложенного SBW и GeckoLib 4.4.9. Все 86 Java-файлов прошли
проверку синтаксиса. Для остальных правок проверено сохранение исходных путей
ресурсов, порядка поиска полей и совместимого наследования рендереров.
Полный проект и Minecraft здесь не запускались: в переданных материалах
отсутствуют скрипты сборки и часть ресурсов. Замер игрового FPS и визуальная
проверка на твоей сборке остаются обязательной частью оценки результата.

В `verification` сохранены исходники проверок и фактический вывод теста.
